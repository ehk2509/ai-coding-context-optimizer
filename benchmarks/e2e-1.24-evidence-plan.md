# ACCO 1.24 end-to-end evidence protocol

This protocol extends the published ACCO 1.22.1 paired SWE-bench experiment
without weakening its publication gate.

The 1.22.1 experiment remains the template for task isolation, randomized
paired trials, hidden-test grading, measured transcript cost, task-cluster
bootstrap confidence intervals, and the rule that savings are publishable only
when task success does not regress.

## Two evidence lanes

### Lane A — 1.24 regression rerun

Re-run the already-published 24-task cohort with ACCO 1.24.0
(commit `6c1689d4c88b20077c475e2aa2b15dc414ad50ee`) and the same Claude Code/model
configuration where still reproducible.

Purpose:

- detect regressions against the 1.22.1 result;
- compare cost/success, tokens, model calls, and per-task behavior;
- verify that the new runtime-activation collector works in real paid runs.

Because this cohort has already been inspected and influenced ACCO development,
the rerun is **not fresh generalization evidence** and must not replace a fresh
headline cohort.

### Lane B — fresh 1.24 headline cohort

Freeze a new cohort before the first ACCO run.

Requirements:

- at least 24 unseen SWE-bench Verified tasks;
- at least 3 paired trials per task;
- no task used by the 1.22.1 frozen cohort or the 2026-09-27 development study;
- prefer at least 6 upstream repositories and a mix of short and iterative tasks;
- freeze exact prompt, revision, hidden test patch, image, test command, model,
  runner, condition profiles, and randomized order before the first paid run;
- commit the manifest and record its task-definition SHA-256 before execution;
- no task substitution or prompt edits after seeing a miss.

The preferred design therefore remains 24 tasks × 3 trials × 2 arms = 144 runs.

## Arms

Baseline:

```text
plain Claude Code
ACCO_DISABLED=1
```

Treatment:

```text
Claude Code + ACCO 1.24.0
acco setup --host claude
run-scoped ACCO_STATE_DIR
```

If provider-boundary interception is enabled for the treatment, that choice is
part of the frozen runner definition and must not change during the experiment.
Do not silently add the provider proxy midway through a cohort.

## Primary endpoint

The primary efficacy endpoint remains:

```text
equivalent API cost per independently solved task
```

Publication requires:

1. frozen broad protocol passes;
2. independent hidden-test grading;
3. treatment success rate >= baseline success rate;
4. task-cluster bootstrap interval for cost-per-success reduction is reported;
5. all failures and failed attempts remain in cost accounting.

Do not turn a token-only reduction into a cost-per-success claim.

## New 1.24 activation evidence

Every enabled run records a content-free `runtime_activation` object before the
temporary worktree is destroyed.

It includes:

- efficiency event counts by event kind;
- ACCO tool calls observed in the Claude transcript;
- Recovery v2 record/object/dependency counts;
- learned tool-field statistics;
- provider-observed cache-TTL evidence;
- output-holdout assignment/observation activity;
- provider/framework observability activity;
- boolean per-run surface activation summaries.

`acco benchmark` aggregates those records under:

```json
{
  "evidence": {
    "runtime_activation": {
      "enabled_runs": 72,
      "runs_with_activation_evidence": 72,
      "coverage_complete": true,
      "surface_runs": {}
    }
  }
}
```

Interpretation is deliberately conservative:

- **activated** means the mechanism actually fired;
- **not activated** means this experiment does not measure that mechanism;
- activation alone does not prove savings or quality;
- efficacy still comes from paired success/cost outcomes.

For a 1.24 feature-specific claim, report the activation denominator. Example:

```text
Recovery v2 was exercised in 31/72 ACCO runs.
```

Do not write "1.24's Recovery v2 caused the saving" unless an experiment or
ablation identifies that causal contribution.

## What should be activated

The fresh cohort should be designed so ordinary agent behavior gives the new
runtime a fair opportunity to activate. Do not add artificial tool calls solely
to inflate activation counts.

Expected surfaces to inspect:

- `recovery_v2`;
- `tool_field_learning`;
- `cache_ttl_learning`;
- `output_holdout` when explicitly enabled in the frozen treatment;
- `provider_observability` when provider interception is part of the treatment;
- `out_of_context_execution`;
- `task_contract`;
- `session_continuity`.

Some surfaces may legitimately remain at zero on SWE-bench. Zero is evidence
about benchmark coverage, not an implementation failure.

## Freezing helper

Use `scripts/prepare_e2e_124_evidence.py` so the runner/image identity and
task-definition hash are generated consistently.

Regression lane:

```bash
python scripts/prepare_e2e_124_evidence.py regression \
  benchmarks/e2e-swebench-24-subscription.frozen.json \
  benchmarks/e2e-swebench-24-1.24-regression.frozen.json
```

Fresh lane, after constructing a candidate suite from previously unused tasks:

```bash
python scripts/prepare_e2e_124_evidence.py fresh \
  benchmarks/e2e-swebench-24-1.24-fresh.candidate.json \
  benchmarks/e2e-swebench-24-1.24-fresh.frozen.json
```

Fresh mode refuses task ids that overlap the published 1.22.1 cohort and
enforces the broad-evidence task/trial floor. Commit the generated frozen
manifest before the first paid run.

## Recommended sequence

1. Merge the activation-evidence harness.
2. Run the old 24-task cohort as a 1.24 regression study.
3. Review activation coverage only; do not tune against fresh-cohort outcomes.
4. Construct and commit the unseen 24-task manifest.
5. Print and commit its task-definition hash before paid execution.
6. Run the 144 paired trials with the resilient runner.
7. Merge shards.
8. Run:

```bash
acco benchmark merged-runs.json \
  --rates benchmarks/claude-sonnet-5-rates-2026-09-19.json \
  --require-publishable
```

9. Publish success, cost-per-success, task-cluster confidence intervals, token
   and model-call deltas, and the activation table together.
10. Keep the 1.22.1 result visible as historical evidence rather than rewriting
    it after the fact.

## Claim ladder

The fresh experiment supports progressively stronger statements only when the
corresponding evidence exists:

```text
activation observed
    ↓
context/token reduction measured
    ↓
success parity established
    ↓
cost-per-success reduction
    ↓
statistically supported reduction
    ↓
feature-specific causal claim (requires ablation)
```

Stop at the highest rung actually demonstrated by the data.
